# BOUN Course Planner

A local course planning tool for Boğaziçi University. Search the full course
catalogue, build a weekly schedule, and see time conflicts immediately.

No build step, no dependencies to run it — just open `index.html`.

## Features

- **Full catalogue search** across all 58 departments/programs, by course code,
  name, or instructor. Case-insensitive, and `CMPE150` / `cmpe 150` both work.
- **Weekly grid** showing lectures, labs, and P.S. sessions with rooms.
- **Conflict detection** — overlapping meetings are outlined in red and listed
  below the grid.
- **Per-course colors**, consistent across reloads, with matching swatches in
  the "My Courses" panel.
- **Credit / ECTS totals** for the selected schedule.
- **Selections persist** in `localStorage`, per semester.

## Running it

Open `index.html` directly in a browser. That's it.

The course data is loaded via `<script src>` rather than `fetch()` specifically
so it works from `file://` without a web server.

If you prefer to serve it over HTTP:

```bash
python -m http.server 8420
```

then visit <http://localhost:8420>.

## Updating the course data

The dataset is generated by a scraper that reads the registrar's public course
schedule pages (no login required).

```bash
pip install -r scraper/requirements.txt
python scraper/scrape_boun.py "2026/2027-1"
```

This writes to `data/`:

| File | Purpose |
| --- | --- |
| `courses-<semester>.json` | Canonical dataset |
| `courses-<semester>.js` | Same data, loadable from `file://` |
| `manifest.json` / `manifest.js` | List of available semesters |
| `departments.json` | Cached department list |

New semesters appear in the dropdown automatically. Pass any semester code
offered by the registrar, e.g. `"2025/2026-2"`.

### Notes on the scraper

- Requests are **sequential and rate-limited** (~0.6s apart) — roughly the same
  load as browsing the department pages by hand. Please keep it that way.
- Transient network errors are retried; if any department still fails, the run
  **aborts without writing**, so a partial scrape can't overwrite good data.
- `departments.json` is cached because the department picker page sits behind a
  reCAPTCHA, while the per-department schedule pages themselves do not.

## Data model

Each section looks like:

```json
{
  "code": "CMPE150",
  "section": "01",
  "department": "COMPUTER ENGINEERING",
  "departmentCode": "CMPE",
  "name": "INTRODUCTION TO COMPUTING",
  "credit": 3,
  "ects": 5,
  "meetings": [
    { "type": "LECT", "instructor": "...", "day": "T", "slot": 8, "room": "EF 06" }
  ]
}
```

Days are `M`, `T`, `W`, `Th`, `F`, `S`. Slots are 1–14, mapping to the
registrar's hourly slots (slot 1 = 09:00, slot 14 = 22:00); the mapping is
included in each dataset as `slotTimes`.
